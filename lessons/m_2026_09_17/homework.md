# Домашнее задание: git (урок 17.09.2026)

Работаем в репозитории `homework_sebastian` — том самом, где лежит `main.py`.

**Правила:**
- Все команды выполняем в терминале, находясь **внутри папки репозитория**.
- После каждого шага смотри `git status` — это главная команда новичка, она всегда подсказывает, что происходит.
- `git push` в этом задании **не делаем**. Всё только локально.
- Если что-то пошло не так — не удаляй папку, а запиши команду и ошибку, разберём на уроке.

## 0. Подготовка

Проверь, что ты внутри репозитория и git знает, кто ты:

```bash
git status
git config user.name
git config user.email
```

Убедись, что ты на ветке `master` и всё чисто:

```bash
git switch master
git status
```

Должно быть написано `nothing to commit, working tree clean`.

## 1. Осмотреться в репозитории

```bash
git log --oneline
```

Ты увидишь список коммитов: слева короткий номер (хеш), справа сообщение.

**Задание:** выпиши в тетрадь/файл ответы:
1. Сколько всего коммитов в репозитории?
2. Какое сообщение у самого первого (нижнего) коммита?

Посмотри, что именно изменилось в последнем коммите:

```bash
git show
```

Нажми `q`, чтобы выйти из просмотра.

## 2. Первый свой коммит

Создай новый файл `practice.md`:

```bash
echo "Любимый язык: Python" > practice.md
```

Посмотри, что видит git:

```bash
git status
```

Файл будет в разделе **Untracked files** — git его видит, но пока не следит за ним.

Добавь файл в индекс (подготовь к коммиту) и проверь статус ещё раз:

```bash
git add practice.md
git status
```

Теперь файл в разделе **Changes to be committed** — он готов к коммиту.

Зафиксируй изменения:

```bash
git commit -m "Добавить файл practice.md"
git log --oneline
```

Твой коммит должен появиться первым в списке.

> **Запомни три состояния файла:**
> изменил → `git add` (положил в коробку) → `git commit` (запечатал и подписал коробку).

---

## 3. Посмотреть и отменить изменения

Измени файл:

```bash
echo "Любимый редактор: VS Code" >> practice.md
```

Посмотри, что конкретно изменилось (`-` удалено, `+` добавлено):

```bash
git diff
```

А теперь **отмени** эти изменения, как будто их не было:

```bash
git restore practice.md
cat practice.md
git status
```

В файле снова одна строка, а рабочая директория чистая.

**Вопрос для себя:** что было бы, если бы перед `git restore` ты успел сделать `git add`? (Подсказка: `git status` в такой ситуации сам пишет нужную команду.)

## 4. Своя ветка

Ветка — это отдельная линия работы, где можно ломать что угодно, не трогая `master`.

Создай ветку `feature-python` и сразу перейди на неё:

```bash
git switch -c feature-python
git branch
```

Звёздочка `*` показывает, на какой ветке ты сейчас.

Измени строку в файле и закоммить:

```bash
echo "Любимый язык: Python 3.12" > practice.md
git add practice.md
git commit -m "Уточнить версию Python"
```

Теперь вернись на `master` и посмотри на файл:

```bash
git switch master
cat practice.md
```

Строка снова старая — изменения остались в ветке. **Это и есть главный смысл веток.**

---

## 5. Слияние веток (merge)

Влей ветку `feature-python` в `master`. Мержим **всегда находясь на той ветке, куда вливаем**:

```bash
git switch master
git merge feature-python
cat practice.md
git log --oneline
```

Изменения приехали в `master`. Конфликта не было, потому что `master` за это время не менялся.

Ветка больше не нужна — удали её:

```bash
git branch -d feature-python
git branch
```

---

## 6. Конфликт и как его починить

Конфликт возникает, когда **одну и ту же строку** изменили в двух ветках по-разному. Сейчас мы создадим его специально.

Создай новую ветку и измени ту же первую строку:

```bash
git switch -c feature-js
echo "Любимый язык: JavaScript" > practice.md
git add practice.md
git commit -m "Поменять язык на JavaScript"
```

Вернись на `master` и измени ту же строку по-другому:

```bash
git switch master
echo "Любимый язык: Python и немного C" > practice.md
git add practice.md
git commit -m "Добавить C к языкам"
```

Теперь пробуй слить:

```bash
git merge feature-js
```

Git ругнётся: `CONFLICT (content): Merge conflict in practice.md`. Это **нормально**, ничего не сломалось.

Посмотри, что внутри файла:

```bash
cat practice.md
```

Увидишь такую разметку:

```
<<<<<<< HEAD
Любимый язык: Python и немного C
=======
Любимый язык: JavaScript
>>>>>>> feature-js
```

- между `<<<<<<< HEAD` и `=======` — версия текущей ветки (`master`);
- между `=======` и `>>>>>>>` — версия ветки, которую вливаем.

**Что делать:** открой `practice.md` в редакторе и оставь тот текст, который считаешь правильным. Например, объедини обе версии в одну строку:

```
Любимый язык: Python, немного C и JavaScript
```

Все служебные строки `<<<<<<<`, `=======`, `>>>>>>>` нужно **удалить полностью**.

Затем скажи git, что конфликт решён, и заверши слияние:

```bash
git add practice.md
git status
git commit -m "Разрешить конфликт в practice.md"
```

Проверь результат:

```bash
cat practice.md
git log --oneline --graph
git branch -d feature-js
```

Флаг `--graph` рисует историю веток «ёлочкой» — найди на ней место, где ветка разошлась и снова слилась.

Должно быть: чистая рабочая директория, только ветка `master`, в истории видно слияние.

## Шпаргалка

| Команда | Что делает |
|---|---|
| `git status` | Что сейчас происходит в репозитории |
| `git add <файл>` | Подготовить файл к коммиту |
| `git commit -m "текст"` | Зафиксировать подготовленное |
| `git log --oneline` | Список коммитов кратко |
| `git diff` | Что изменил, но ещё не добавил в `add` |
| `git show` | Что было в последнем коммите |
| `git restore <файл>` | Отменить незакоммиченные правки в файле |
| `git branch` | Список веток (`*` — текущая) |
| `git switch <ветка>` | Перейти на ветку |
| `git switch -c <ветка>` | Создать ветку и перейти на неё |
| `git merge <ветка>` | Влить ветку в текущую |
| `git branch -d <ветка>` | Удалить ненужную ветку |
